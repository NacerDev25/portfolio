## 1. القرار المقترح: صفحة Home منفصلة

### التوصية

**نعم — يُنصح بإضافة صفحة `Home` مستقلة عن `About`، بشرط صارم: كل صفحة تجيب على سؤال واحد، وما تتكررش أي جملة بينهما.**

### المبرّر

| البُعد | Home | About |
|---|---|---|
| السؤال المُجاب | "كيف أستفيد منك؟" | "مين أنت؟" |
| زمن القارئ | 5 ثوانٍ | دقيقتان |
| الدافع | وصل من LinkedIn / بحث / رابط | قرّر يهتم فعلاً |
| نية SEO | "web developer portfolio" | "about [اسمك] developer" |

بدون الفصل: صفحة واحدة تحاول خدمة نيتين ← **keyword cannibalization** + تكرار.
مع الفصل: `index.html` = صفحة الهبوط (URL `/`)، و`about.html` = القصة الكاملة.

### ⚠️ الشرط الصارم (فخ التكرار)

| | Home | About |
|---|---|---|
| يجيب عن | "ماذا أقدّم لك؟" | "مين أنت؟" |
| المحتوى | Hero (اسم + تخصص + عرض واحد) · الخدمات باختصار · 3 مشاريع مختارة + "عرض الكل" · CTA | القصة (بدون إعادة الـ hero) · المهارات بالتفصيل · المسار المهني (timeline) · التعليم والشهادات · اللغات |

- "الأعمال المختارة" في Home **ليست** شبكة Projects — بل 3 عناصر + رابط "عرض الكل".
- لا يُستعمل نفس نص الـ Hero في الاثنتين.

### تحفّظ على التوقيت

`index.html:133` — الـ `about-body` فارغ تماماً. القرار يعتمد على حجم المحتوى:

- لو الـ About = فقرة + شبكة مهارات → **صفحة واحدة تكفي** و Home يولّد تكراراً
- لو الـ About = 3–4 شاشات (timeline + شهادات + آراء عملاء) → **الفصل مبرّر**

**التوصية:** نفّص الفصل الآن، مع كتابة محتوى كل صفحة بجملة وظيفتها واحدة.

### أثر ذلك على ملف المرجع

السطران **10** و **36** من `مرجع_معرض_الأعمال.txt` يدمجان Home/About في "الرئيسية / عني" — يجب تحديثهما رسمياً إلى 5 صفحات.

## 2. الأثر التقني الإجباري (إلا إذا قرار 4 اختلف)

### 2.1 عنوان الصفحة لازم يولي لكل صفحة (WCAG 2.4.2)

حالياً `js.js` يضبط `document.title = translation.title` — قيمة واحدة عامة (`"About Me | Portfolio"`).
مع 5 صفحات يجب أن يُشتق العنوان من الصفحة الحالية:

```js
const pageKey = document.body.dataset.page;   // "home" | "about" | "projects" | "services" | "contact"
document.title = `${t.pages[pageKey].title} | ${t.site.name}`;
```

### 2.2 تمييز الصفحة النشطة يُحسب من الملف (WCAG 3.2.3)

حالياً `is-active` **مكتوب يدوياً** في HTML (`index.html:32`، `index.html:91`) — وهذا أول bug عند إضافة أي صفحة.
الحل: يُحسب في JS من اسم الملف:

```js
const currentPage = location.pathname.split("/").pop() || "index.html";
document.querySelectorAll("[data-page]").forEach((link) => {
  link.classList.toggle("is-active", link.getAttribute("href") === currentPage);
});
```

### 2.3 هيدر وفوتر — التكرار ×5

| الخيار | المزايا | العيوب |
|---|---|---|
| **أ) JS injection** (سطر 51 من المرجع) | تعديل مرة واحدة | Flash of unstyled content · الهيدر غير مرئي لمحركات البحث |
| **ب) HTML ثابت ×5** | SEO كامل · بلا FOUC | 5 نسخ تتطلب تزامناً يدوياً |
| **ج) HTML ثابت + اختبار تزامن** ✅ *موصى به* | SEO كامل · تعديلات محصورة · **اختبار آلي يمنع الانحراف** | 5 نسخ على القرص (يقبلها الاختبار) |

**التوصية (ج):** نُبقي HTML ثابتاً في كل صفحة، ونضيف اختبار آلي يقارن الهيدر والفوتر في الصفحات الخمس ونبشل إن اختلفوا. النتيجة = "يُعدَّل مرة واحدة ويُطبَّق على الكل" **بدون** حجب SEO وبدون build step.

### 2.4 رابط التخطي يتكرر في كل صفحة

`<a class="skip-link" href="#main-content">` + `<main id="main-content" tabindex="-1">` — متكرر في كل صفحة (مكوّن واحد يبقى ثابت).

### 2.5 معمارية i18n المقترحة (تحسين جوهري)

النظام الحالي: 3 كائنات منفصلة (`en` / `ar` / `fr`) بنفس المفاتيح — إضافة نص = **3 أسطر متفرقة**.
النظام المقترح: **قيم متعددة اللغات داخل المفتاح الواحد** → إضافة نص = **سطر واحد**:

```js
const translations = {
  site: {
    name: { en: "Nasro Portfolio", ar: "معرض nasro", fr: "Portfolio Nasro" }
  },
  shared: {
    skipToContent: { en: "Skip to main content", ar: "تخطَّ إلى المحتوى الرئيسي", fr: "Aller au contenu principal" },
    navHome: { en: "Home", ar: "الرئيسية", fr: "Accueil" }
  },
  pages: {
    home: {
      title: { en: "Home", ar: "الرئيسية", fr: "Accueil" },
      hero: {
        heading: { en: "...", ar: "...", fr: "..." },
        cta: { en: "...", ar: "...", fr: "..." }
      }
    },
    about: { /* ... */ },
    projects: { /* ... */ },
    services: { /* ... */ },
    contact: { /* ... */ }
  }
};

function translate(key, lang) {
  return key.split(".").reduce((node, part) => (node ? node[part] : undefined), translations)?.[lang];
}
```

**المزايا:** صيانة أعلى · مفاتيح الصفحة الجديدة تُضاف في مكان واحد · لا خطر نسيان لغة.

### 2.6 تقسيم الملفات

حالياً 3 ملفات مسطّحة. مع 5 صفحات يتضخّم `js.js` (قد يتجاوز 700 سطر). الخيارات:

| أ) مسطّح (现状) | ب) منظّم (موصى به) |
|---|---|
| `index.html`, `about.html`, ... | `index.html`, `about.html`, ... |
| `style.css` | `css/base.css`, `css/chrome.css`, `css/pages.css` |

| | `data/profile.js` (الاسم، التخصص، التواصل، المهارات) |

لا framework — HTML/CSS/JS نقي كما ينصّ المرجع.

### 2.7 بنية المحتوى: HTML ثابت أم بيانات JS؟

| الخيار | المميزات | العيوب |
|---|---|---|
| **أ) HTML + قاموس i18n** ✅ *موصى به* | SEO كامل · ترتيب منطقي · مطابق لنظام `data-i18n` الحالي | قاموس الترجمة يكبر مع المحتوى |
| ب) بيانات JS تُرسم ديناميكياً | المحتوى في ملف واحد قابل للتعديل | المحتوى غير مرئي لمحركات البحث |
| ج) صفحة HTML لكل لغة | SEO ممتاز لكل لغة | 15 ملف HTML · صيانة ثقيلة |

**التوصية (أ):** HTML يحوي المحتوى الإنجليزي (الافتراضي) مع مفاتيح `data-i18n`، والقاموس يحمل en/ar/fr.

## 8. معايير القبول (Definition of Done)

يُعتبر أي مرحلة منجزة إذا:

1. `node --check` على كل ملف JS يمرّ
2. اختبار DOM (jsdom) يمرّ بالكامل لكل صفحة
3. الفحص الثابت يمرّ (ids · مفاتيح الترجمة · عدم تكرار)
4. الصفحة تعمل بـ HTTP 200 وكل أصولها تُحمّل بلا 404
5. لا أخطاء ولا تحذيرات في الـ console
6. التنقل بالكيبورد كامل: Tab · Shift+Tab · Enter · Space · Esc
7. التبديل بين اللغات والاتجاهين يعمل في كل صفحة
8. الوضع الفاتح والداكن مقروءان بتباين ≥ 4.5:1
9. التفضيلات محفوظة وتُسترجع بعد إعادة التحميل
10. رابط التخطي يعمل في كل صفحة
11. العنوان والوصف الفارغ غير موجودين
12. تمرّ على Lighthouse ≥ 95 في Accessibility
